====================================================================
 APS HEALTH - SISTEMA DE GESTAO CLINICA
 PASSO A PASSO COMPLETO PARA EXECUTAR, USAR E APRESENTAR
====================================================================

Este documento explica TUDO o que precisa ser feito para subir e usar
a aplicacao: frontend + backend (3 microsservicos + 3 bancos MongoDB),
o login por perfil, o fluxo de uso, como fazer deploy em uma VM gratuita
e como demonstrar a tolerancia a falhas em uma apresentacao.

--------------------------------------------------------------------
1. REQUISITOS
--------------------------------------------------------------------
- Docker Desktop (Windows/Mac) ou Docker Engine (Linux) instalado e em
  execucao. Ja inclui o Docker Compose.
- Opcional: MongoDB Compass para inspecionar os bancos.

Nao e necessario instalar Python nem Node: tudo roda em containers,
inclusive o frontend.

Portas usadas na maquina (precisam estar livres):
- 8080  frontend (site)
- 5001  cadastro-service        - 27017 cadastro-mongo
- 5002  faturamento-service     - 27019 faturamento-mongo
- 5003  agendamento-service     - 27018 agendamento-mongo

--------------------------------------------------------------------
2. ARQUITETURA QUE SERA INICIADA
--------------------------------------------------------------------
Cada microsservico tem o seu PROPRIO banco MongoDB (database per
service) e um volume persistente proprio. Todos compartilham apenas
uma rede Docker interna (aps-health-net) para se comunicarem por nome.

  frontend            (8080) ---> chama os 3 servicos via REST/JSON
  cadastro-service    (5001) ---> cadastro-mongo    (db aps_health_cadastro)
  agendamento-service (5003) ---> agendamento-mongo (db aps_health_agendamento)
  faturamento-service (5002) ---> faturamento-mongo (db aps_health_faturamento)

Comunicacao entre servicos (REST/JSON, dentro da rede Docker):
  agendamento -> cadastro    : valida paciente, medico e especialidade
  agendamento -> faturamento : obtem valor vigente da consulta
  agendamento -> faturamento : emite cobranca ao finalizar a consulta

Seguranca / controle de acesso:
  - O login emite um token JWT (cadastro-service).
  - As operacoes de escrita (criar/editar/remover) sao protegidas por
    perfil (RBAC). As leituras ficam abertas.
  - As chamadas internas entre servicos usam um token interno
    (X-Internal-Token), configurado no docker-compose.yml.

--------------------------------------------------------------------
3. SUBIR TUDO (UM UNICO COMANDO)
--------------------------------------------------------------------
1) Abra o terminal na pasta "docker" do projeto.
2) Execute:

     docker compose up --build -d

   - "--build" reconstroi as imagens (use sempre que o codigo mudar).
   - "-d" sobe em segundo plano (modo "detached").

3) Acompanhe ate todos ficarem prontos:

     docker compose ps

   Os 3 *-mongo aparecem como "healthy"; depois sobem os 3 *-service e
   o frontend (os bancos sobem primeiro, por depends_on + healthcheck).

Para ver os logs (todos ou de um servico especifico):

     docker compose logs -f
     docker compose logs -f agendamento-service

--------------------------------------------------------------------
4. ACESSAR O SITE E FAZER LOGIN
--------------------------------------------------------------------
Abra no navegador:

     http://localhost:8080

A tela de login tem uma CAIXA DE SELECAO do tipo de acesso (perfil),
mais usuario e senha. Em caso de credenciais erradas, aparece a
mensagem "Login invalido".

Usuarios administrativos padrao (criados automaticamente na 1a subida):

     Perfil       Usuario      Senha
     ---------    ---------    -----------
     Diretor      diretor      diretor123
     Gerente      gerente      gerente123
     Atendente    atendente    atendente123
     Medico       medico       medico123

O PACIENTE cria o proprio acesso: na tela de login clique em
"Criar cadastro", preencha os dados + usuario e senha. Ele ja entra
logado na area do paciente.

Verificacao rapida do backend (opcional) - cada servico expoe /health:

     http://localhost:5001/health   -> Cadastro Service funcionando
     http://localhost:5002/health   -> Faturamento Service funcionando
     http://localhost:5003/health   -> Agendamento Service funcionando

--------------------------------------------------------------------
5. ORDEM CORRETA DE USO (IMPORTANTE)
--------------------------------------------------------------------
O agendamento valida disponibilidade real. Para conseguir agendar uma
consulta, os pre-requisitos abaixo precisam existir, nesta ordem:

  1) Logado como DIRETOR:
       - Cadastrar ESPECIALIDADE
       - Cadastrar CONSULTORIO
       - Definir VALOR VIGENTE (valor + data). Esse valor fica
         "congelado" na consulta no momento do agendamento.

  2) Logado como GERENTE:
       - Cadastrar MEDICO (vincule ao menos uma especialidade).
       - Criar ESCALA do medico (medico, consultorio, dia da semana,
         vigencia e horario). A escala define QUANDO o medico atende.
         Sem escala que cubra o dia/horario, o agendamento e recusado.

  3) Logado como ATENDENTE (apoio operacional):
       - Cadastrar/atualizar PACIENTES, cadastrar MEDICAMENTOS e EXAMES,
         registrar PAGAMENTOS.

  4) PACIENTE (cadastro proprio na tela de login):
       - Consultar disponibilidade do medico por data;
       - Agendar consulta (data/hora precisam cair numa escala livre);
       - Reagendar / solicitar cancelamento (so antes do horario e
         enquanto a consulta estiver AGENDADA);
       - Acompanhar suas consultas, cobrancas e pagamentos.

  5) MEDICO (login medico/medico123, selecione seu registro):
       - Visualiza suas escalas e consultas;
       - Inicia a consulta (-> EM_ANDAMENTO);
       - Prescreve medicamentos, solicita exames, registra resultados;
       - Encerra a consulta (-> FINALIZADA). Ao encerrar, uma COBRANCA
         e emitida automaticamente no Faturamento.

  6) GERENTE: aprova ou rejeita as solicitacoes de cancelamento
     pendentes. Ao aprovar, a consulta vira CANCELADA.

Estados da consulta: AGENDADA -> EM_ANDAMENTO -> FINALIZADA
                     AGENDADA -> CANCELADA (via aprovacao do gerente)

--------------------------------------------------------------------
6. TOLERANCIA A FALHAS - COMPORTAMENTO E ROTEIRO DE DEMONSTRACAO
--------------------------------------------------------------------
Comportamento esperado com servicos fora do ar:

- Faturamento indisponivel:
  * O agendamento PROSSEGUE; a consulta e criada com valor nulo
    (degradacao graciosa).
  * Ao finalizar, a cobranca apenas nao e emitida (pode ser lancada
    manualmente depois).

- Cadastro indisponivel:
  * A operacao que depende de validacao retorna erro controlado 503
    (servico indisponivel), sem derrubar os demais servicos.

ROTEIRO PARA APRESENTAR (passo a passo):

  Preparacao (com tudo no ar): faca os cadastros do item 5 (1 e 2),
  crie um paciente e deixe-o logado. Deixe um terminal aberto mostrando
  "docker compose ps".

  CENARIO 1 - Faturamento cai, agendamento continua:
     docker compose stop faturamento-service
  -> No site, como paciente, agende uma consulta num horario da escala.
     Funciona, mas a consulta fica SEM valor (valor nulo).
     Frase-chave: "mesmo com o Faturamento fora, o paciente agendou".
     docker compose start faturamento-service

  CENARIO 2 - Cadastro cai, erro controlado (sem efeito cascata):
  ATENCAO: faca o login ANTES de derrubar o cadastro (o login usa o
  cadastro). Estando logado:
     docker compose stop cadastro-service
  -> Tente agendar: o sistema responde com erro controlado 503
     (servico indisponivel), sem travar. Mostre que faturamento e
     agendamento seguem de pe (docker compose ps / .../5003/health).
     docker compose start cadastro-service

  Conclusao demonstrada: a indisponibilidade de um microsservico NAO
  derruba os demais (requisito de tolerancia a falhas do minimundo).

--------------------------------------------------------------------
7. INSPECIONAR OS BANCOS MONGODB (OPCIONAL)
--------------------------------------------------------------------
Cada Mongo esta exposto em uma porta diferente da maquina:

  cadastro-mongo     mongodb://localhost:27017   (db aps_health_cadastro)
  agendamento-mongo  mongodb://localhost:27018   (db aps_health_agendamento)
  faturamento-mongo  mongodb://localhost:27019   (db aps_health_faturamento)

Use o MongoDB Compass com essas URIs, ou o mongosh dentro do container:

     docker exec -it cadastro-mongo mongosh aps_health_cadastro
     > db.pacientes.find()
     > db.usuarios.find()     (usuarios de login + senha com hash)

A colecao "counters" controla os ids sequenciais. NAO a remova se
quiser preservar a contagem.

--------------------------------------------------------------------
8. PARAR / REINICIAR / RESETAR
--------------------------------------------------------------------
Parar mantendo os dados:        docker compose stop
Subir novamente (sem rebuild):  docker compose up -d
Derrubar os containers:         docker compose down
Resetar TUDO (apaga os bancos): docker compose down -v
Reconstruir apos mudar codigo:  docker compose up --build -d

--------------------------------------------------------------------
9. DEPLOY EM UMA VM GRATUITA (para deixar acessivel na internet)
--------------------------------------------------------------------
A forma mais simples de manter a arquitetura atual e rodar o mesmo
docker-compose em uma VM. Uma opcao gratuita permanente e a
Oracle Cloud Always Free.

  1) Criar a VM:
     - Conta em cloud.oracle.com -> Compute -> Instances -> Create.
     - Imagem Ubuntu; shape Always Free (VM.Standard.A1.Flex ou
       E2.1.Micro). Baixe a chave SSH.

  2) Abrir as portas (a parte mais chata da Oracle):
     - No painel: VCN -> Security List -> Ingress Rules -> liberar
       TCP 8080, 5001, 5002, 5003.
     - Na VM (Ubuntu da Oracle bloqueia por iptables):
         sudo iptables -I INPUT 6 -m state --state NEW -p tcp \
           -m multiport --dports 8080,5001,5002,5003 -j ACCEPT
         sudo netfilter-persistent save

  3) Instalar o Docker na VM:
         curl -fsSL https://get.docker.com | sudo sh
         sudo usermod -aG docker $USER   (saia e entre no SSH de novo)

  4) Trazer o codigo e subir:
         git clone <URL_DO_REPOSITORIO>
         cd Sistema-Clinicas-Microsservicos/docker
         docker compose up --build -d

  5) Acessar:  http://SEU_IP_PUBLICO:8080

Observacao sobre as URLs: o frontend descobre sozinho o endereco dos
servicos a partir do host usado para abrir o site (ex.: abrindo
http://SEU_IP:8080, ele chama http://SEU_IP:5001/5002/5003). Se precisar
apontar para outro host/portas, edite frontend/config.js.

Dica: para a DEMONSTRACAO de tolerancia a falhas, rodar LOCALMENTE
(secao 6) e o mais confiavel, pois o "stop/start" e instantaneo e voce
controla exatamente qual servico esta fora do ar.

--------------------------------------------------------------------
10. PROBLEMAS COMUNS
--------------------------------------------------------------------
- "Login invalido": usuario/senha incorretos ou perfil selecionado
  diferente do perfil do usuario. Confira as credenciais da secao 4.

- "Acesso negado para o seu perfil" (403): voce tentou uma acao que
  pertence a outro perfil. Entre com o perfil correto (secao 5).

- "Horario indisponivel" ao agendar: o medico nao tem escala que cubra
  aquele dia/horario, ou a data ja passou. Crie a escala (secao 5.2).

- "porta ja em uso": outro processo usa 8080/5001/5002/5003 ou
  27017-27019. Pare o processo conflitante ou ajuste as portas no
  docker-compose.yml.

- Site abre mas nada carrega: confirme que os servicos estao no ar
  (docker compose ps) e acessiveis (secao 4).

- Mudei o codigo e nada mudou: refaca com "--build".

- Docker nao instalado/parado: instale/abra o Docker Desktop e rode de
  novo "docker compose up --build -d" dentro da pasta docker.

--------------------------------------------------------------------
11. RESUMO RAPIDO
--------------------------------------------------------------------
  cd docker
  docker compose up --build -d     # sobe frontend + 3 servicos + 3 Mongo
  docker compose ps                # confere os containers
  # navegador: http://localhost:8080
  # login: diretor/diretor123, gerente/gerente123, atendente/atendente123,
  #        medico/medico123 ; paciente cria o proprio acesso
  # ordem de uso: especialidade > consultorio > valor (diretor) >
  #               medico > escala (gerente) > cadastro paciente > agendar
  # demo de falha: docker compose stop/start faturamento-service
